৪প্রথমবার deploy: ধাপে ধাপে যা করা হয়েছে

  1. Online database বানানো। Supabase-এ নতুন free project asdc-diagnostic, region Mumbai (ap-south-1)। Local কম্পিউটারের database Vercel থেকে পৌঁছানো যায় না, তাই online database লাগে।
  2. Git ঠিক করা। Project-এর .git folder ভাঙা ছিল, তাই git init -b main দিয়ে নতুন করে শুরু, তারপর প্রথম commit। .env* আর log file commit-এ যায়নি তা যাচাই করা হয়েছে।
  3. GitHub-এ পাঠানো। github.com/new-এ খালি private repo বানিয়ে: 
    git remote add origin https://github.com/msibd/asdc-diagnostic.git
git push -u origin main
  4. Secret বানানো। BETTER_AUTH_SECRET আর EMAIL_ENCRYPTION_KEY random বানিয়ে .env.vercel file-এ রাখা হয়েছে (git-এ যায় না)।
  5. Vercel-এ import। vercel.com/new → msibd/asdc-diagnostic → Import। Environment Variables-এ .env.vercel-এর লেখা paste করে আসল password বসানো, তারপর Deploy।
  6. Build-এর error ঠিক করা। pnpm, database password, connection limit ইত্যাদি সমস্যা পরপর এসেছে, পরের অধ্যায়ে বিস্তারিত।
  7. Admin account বানানো। Online database-এ কোনো user ছিল না। Admin বানানো হয়েছে (অধ্যায় ৮)।
  8. Connection-এর সমস্যা স্থায়ীভাবে ঠিক করা। DATABASE_URL port 6543, DIRECT_URL port 5432, connection pool ছোট করা, Vercel-এ realtime বন্ধ, region Mumbai।
  9. শুরুর data। Test catalog, website-এর লেখা আর demo data বসানোর script চালু করা হয়েছে (অধ্যায় ১১ দেখুন)।

৬প্রতিদিনের update deploy করা

Code বদলানোর পর শুধু GitHub-এ push করুন। Vercel ২-৩ মিনিটে নিজে থেকেই নতুন version চালু করবে।

  1. নিজের কম্পিউটারে পরীক্ষা: 
    pnpm install
pnpm exec tsc --noEmit
pnpm build
  2. Commit ও push: 
    git add -A
git commit -m "কী বদলেছেন তার ছোট বর্ণনা"
git push
  3. Vercel → Deployments-এ নতুন deploy Building → Ready হওয়া দেখুন। Error হলে deploy-এ click করে Build Logs-এর লাল অংশ পড়ুন, অধ্যায় ৫-এ মিলিয়ে দেখুন।
  4. Site-এ Ctrl+Shift+R দিয়ে নতুন version দেখুন।
পুরনো version-এ ফেরত যাওয়া (Rollback) নতুন version-এ বড় সমস্যা হলে: Deployments → আগের যে deploy ঠিক চলছিল → ⋯ → Promote to Production। এক click-এ পুরনো version ফিরে আসে। (Database-এর পরিবর্তন এতে ফেরে না।)
Claude দিয়ে করাতে চাইলে "এই পরিবর্তন commit করে push করো" বললেই হবে। কিন্তু Vercel connector-এর অনুমতি কাজ না করায় Vercel-এর ভেতরের setting আপনাকে নিজে বদলাতে হবে।

৭Database-এ নতুন migration চালানো

যখন prisma/schema.prisma বদলে নতুন migration বানানো হয় (prisma/migrations/-এ নতুন folder), তখন online database-এও সেটা বসাতে হবে। Build এখন নিজে থেকে এটা করে না।

ক্রম গুরুত্বপূর্ণ আগে migration online database-এ চালান, তারপর code push করুন। উল্টো করলে নতুন code পুরনো database-এ চলে error দেবে।

Project folder-এ PowerShell খুলে (port 5432, PASSWORD-এর জায়গায় database password):

$env:DIRECT_URL = "postgresql://postgres.xelbpwwphgkhthozkriy:PASSWORD@aws-0-ap-south-1.pooler.supabase.com:5432/postgres"
pnpm prisma migrate status
pnpm prisma migrate deploy
Remove-Item Env:DIRECT_URL

migrate status দেখায় কোনগুলো বাকি; migrate deploy সেগুলো বসায়। শেষ লাইনটা password মুছে দেয়। এরপর git push।

এখনকার অবস্থা Repo-তে ৩৪টা migration, online database-এ ৩৪টাই বসানো।

৮Admin account বানানো / password reset

নতুন database-এ প্রথম admin

$env:DATABASE_URL = "postgresql://postgres.xelbpwwphgkhthozkriy:PASSWORD@aws-0-ap-south-1.pooler.supabase.com:6543/postgres"
$env:ADMIN_NAME = "Administrator"
$env:ADMIN_EMAIL = "mmbdsafik@gmail.com"
pnpm db:seed

Script জিজ্ঞেস করবে "Create administrator password": এখানে login-এর নতুন password (কমপক্ষে ১০ অক্ষর) দিন। প্রথমে যে PASSWORD বসিয়েছেন সেটা database password; এখানে যেটা দেবেন সেটা login password। দুটো আলাদা।

Admin password ভুলে গেলে

উপরের মতো $env:DATABASE_URL বসিয়ে:

pnpm admin:reset-password
কাজ শেষে PowerShell window বন্ধ করে দিন। $env: দিয়ে বসানো মান শুধু ওই window-তে থাকে, বন্ধ করলে মুছে যায়। .env.local বদলাতে হয় না।

আটকে থাকা database connection বন্ধ করা

Supabase → SQL Editor-এ চালান। এটা শুধু অলস (idle) connection বন্ধ করে, কোনো data মোছে না; app দরকার হলে আবার connect করে।

select count(*) filter (where pg_terminate_backend(pid)) as closed
from pg_stat_activity
where application_name = 'Supavisor' and state = 'idle';

এখন কতগুলো connection খোলা

select application_name, state, count(*)
from pg_stat_activity
where datname = 'postgres'
group by 1, 2 order by 3 desc;

১০নিরাপত্তার নিয়ম

  • Password কোথাও লিখবেন না: chat, screenshot, code, GitHub, এই নির্দেশিকা। Screenshot-এ password দেখা গেলে সেটা সাথে সাথে বদলান।
  • .env.local ও .env.vercel কখনো commit করবেন না। .gitignore এগুলো আটকায়; git status-এ এগুলো দেখা গেলে থামুন।
  • Database password আর admin login password আলাদা রাখুন।
  • Demo account (admin@demo.example ইত্যাদি) random password পেয়েছে যা কেউ জানে না; SEEDING.md-এর demo password live site-এ কাজ করে না। কখনো DEMO_*_PASSWORD ছাড়া demo seed live database-এ চালাবেন না।
  • EMAIL_ENCRYPTION_KEY ও BETTER_AUTH_SECRET নিরাপদ জায়গায় backup রাখুন। হারালে নতুন বানানো যায়, কিন্তু তাতে সবাই logout হবে আর সেভ করা email password আবার দিতে হবে।
  • GitHub repo private রাখুন।

১২শূন্য থেকে নতুন করে deploy (checklist)

নতুন account বা নতুন database-এ পুরো system আবার চালু করতে এই ক্রমে যান।

  • Supabase-এ নতুন project (region Mumbai), database password শুধু অক্ষর+সংখ্যা।
  • Supabase → Connect থেকে transaction pooler (6543) ও session pooler (5432) URI কপি।
  • Migration: $env:DIRECT_URL = 5432 URI, তারপর pnpm prisma migrate deploy।
  • দুটো নতুন random secret বানানো (BETTER_AUTH_SECRET, EMAIL_ENCRYPTION_KEY)।
  • GitHub-এ code push (private repo)।
  • vercel.com/new → repo Import → Environment Variables (অধ্যায় ৩-এর সব) → Deploy।
  • Deploy Ready হলে আসল ঠিকানা দেখে BETTER_AUTH_URL ঠিক করে Redeploy।
  • প্রথম admin: pnpm db:seed (অধ্যায় ৮)।
  • দরকার হলে pnpm db:seed:lab আর pnpm db:seed:website।
  • Login করে Dashboard, Bookings, Patients, Billing খুলে দেখা।
  • Supabase → Logs → Pooler-এ EMAXCONN আসছে না তা নিশ্চিত হওয়া।
মনে রাখার তিনটা কথা ১) DATABASE_URL = 6543, DIRECT_URL = 5432। ২) Variable বদলালে Redeploy। ৩) নতুন migration আগে চালান, তারপর push।
